# Design

## Theme tokens

All design tokens live in `src/styles/globals.css` — Tailwind v4 CSS-first
config, no `tailwind.config.js`. The structure:

- `:root` and `.dark` define the semantic palette as CSS custom properties
  (`--background`, `--foreground`, `--primary`, `--muted`, `--destructive`,
  `--border`, `--input`, `--ring`, …) in OKLCH.
- `@theme inline` maps those variables into Tailwind's namespace
  (`--color-background` → `bg-background`, etc.) plus the radius scale
  derived from a single `--radius` (0.625rem).
- Current palette: shadcn **neutral** base color, **new-york** style —
  byte-identical to the registry defaults.

To retheme a project: change the values in `:root` / `.dark` (and `--radius`)
only. Do not rename tokens and do not add colors outside the semantic set
without documenting them here. Components must use semantic classes
(`bg-background`, `text-muted-foreground`) — never raw palette values.

## Dark mode

Class strategy: a `dark` class on `<html>`, wired up as
`@custom-variant dark (&:is(.dark *))` in `globals.css`.

- The user's choice is a global Jotai atom, `themeAtom` in `src/store/theme.ts`
  (`atomWithStorage`, persisted to `localStorage` under the key `theme`).
- `components/shared/ThemeToggle.tsx` reads/writes the atom and applies the
  class to `document.documentElement`.
- Default is light; there is no system-preference detection yet. If a project
  needs it, extend the atom to a `'light' | 'dark' | 'system'` union and
  resolve `system` against `prefers-color-scheme` — and update this doc.

## shadcn/ui usage

- Style: `new-york`, base color `neutral`, CSS variables on, lucide icons
  (see `components.json`).
- Installed primitives: `button`, `card`, `form`, `input`, `label`,
  `textarea`.
- Primitives in `src/components/ui/` are exempt from ESLint, Prettier and
  knip so they stay byte-identical to the registry output. They are still
  type-checked.
